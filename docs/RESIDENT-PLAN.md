# JARVIS resident navigation implementation plan

Goal: retain Ripwire's existing MCP index for native Pi `search` and `task` requests; keep CLI-only actions unchanged. Measurements before implementation: `local-validation/runs/jarvis-resident-measure-01/result.json` outside this repo. Warm MCP grep ~35ms (pi-optchat), ~310ms (Genexus18MCP), identical response hashes; not CLI-output parity or whole-agent speed.

Architecture: a session-owned stdio MCP pool, at most two repository-rooted processes; serialized bounded requests per server. No socket, daemon installation, external provider or global executable change. Core navigation persists the normal receipt plus explicit transport/freshness metadata; MCP tool errors remain errors. The feature is opt-in with `PI_RIPWIRE_RESIDENT=1` while validation is pending. No fallback/replay after a dispatched request fails.
